# 架构与边界

Tk 主线程定时读取 SQLite 和后台快照。`ui.py`、`ui_theme.py`、`ui_widgets.py` 负责交互、样式、虚拟表格，后台通过线程安全队列报告事件，不直接操作控件。

`parser.py` 提取活动、时区明确的报名窗口及取消信息；`storage.py` 用独立连接和事务保存活动、档案、变更和任务，`claim_job` 原子领取已开放任务，不确定提交不自动重试。

`receiver/preload.cjs` 观察 QQ 已有会话，保留原回调和方法接收者，只发送白名单群。每 15 秒补读记录、去重，心跳与消息分别调度，队列有界。

`bridge.py` 只监听本机回环，`POST /events` 限请求大小并校验令牌、群号和时间；`GET /health` 不返回令牌。运行配置在用户本机，不进入仓库。

`qq_setup.py` 配置独立启动器，不写 QQ 安装文件；用户显式点击重启才关闭相同路径的 QQ。`native_boot.py` 和原生 C 组件检查版本和指纹，启动新进程并在内存加载本项目 DLL；不兼容则拒绝。研究边界和隔离测试见原生目录说明。

`booking.py` 的单一线程拥有 Playwright 和独立 Edge 资料。已到期任务优先，其次登录核验及低优先级表单预检；临近报名推迟一般检查。登录在官方账户页确认，题目及选项按真实表单读取，每人使用新页面，提交前复查时间、答案、去重限制和活动变更。

QQ 和 WPS 页面更新可能需要重新适配。测试使用临时数据库、模拟目录、拦截的可控表单，不用用户资料或真实提交证明测试成功。
